## 1. Ringkasan

M5 membuat aplikasi bisa dipamerkan tanpa didampingi:

- Setiap perubahan status penting menulis **notifikasi simulasi** untuk penerima yang tepat.
  Lonceng di header menampilkan jumlah belum dibaca; halaman `/notifikasi` menjadi log lengkap.
- Izin distribusi dicetak **A4 satu halaman**, tanpa menu aplikasi atau toast, dan izin koreksi
  mencantumkan nomor izin yang digantikan beserta alasannya.
- `npm run share` membuka akses lintas perangkat lewat satu tunnel web + API.
- `README.md` dan `docs/panduan-demo.md` bisa diikuti dari nol, termasuk skenario demo 5 menit.
- Bundel peta dipisah sehingga bundel awal turun dari sekitar 705 kB menjadi sekitar 213 kB.

### 2.3 Verifikasi otomatis

```
npm run verify:m1   18 pemeriksaan lulus, 0 gagal
npm run verify:m2   49 pemeriksaan lulus, 0 gagal
npm run verify:m3   80 pemeriksaan lulus, 0 gagal
npm run verify:m4   99 pemeriksaan lulus, 0 gagal
npm run verify:m5   40 pemeriksaan lulus, 0 gagal
```

Pemeriksaan M5 mencakup:

1. Notifikasi menolak permintaan tanpa sesi (`401`) dan bisa dibuka semua peran.
2. Kondisi seed bersih: **0 notifikasi**.
3. Setiap perpindahan status menambah notifikasi pelapor; pengajuan juga menambah notifikasi
   pimpinan.
4. Notifikasi persetujuan memuat nomor izin; notifikasi koreksi memuat nomor izin lama dan baru.
5. Tandai satu/tandai semua dibaca mengurangi jumlah belum dibaca.
6. Notifikasi milik pengguna lain tidak bisa ditandai (isolasi `userId`).
7. Pesan bebas istilah mesin (`payload`, `webhook`, `exception`, `undefined`, `http`, `sql`).
8. Reset mengembalikan **0 laporan dan 0 notifikasi**.
9. Skrip `npm run share`, host tunnel Vite, aturan cetak A4, README, dan panduan demo tersedia.

### 2.4 Akses lintas perangkat

`npm run share` diuji dua tahap:

- **Uji singkat** (`SHARE_SMOKE=1`): tunnel terbuka, URL tercetak, kata sandi halaman pengingat
  ikut tercetak, lalu tunnel ditutup otomatis.
- **Uji alamat publik:** halaman web dibuka lewat URL tunnel → `200`; `/api/health` lewat tunnel
  → `200` dengan `{"ok":true,"demoMode":true,"database":"ok"}`. Artinya web, proxy API, dan
  sesi cookie bekerja dari luar komputer demo.

## 3. Notifikasi

Setiap perpindahan status menulis satu baris untuk setiap penerima (satu peristiwa bisa menjadi
beberapa baris):

| Peristiwa | Penerima | Contoh judul |
| :--- | :--- | :--- |
| Laporan dibuat | Pelapor | Laporan tersimpan |
| Estimasi dihitung | Pelapor | Estimasi bantuan siap |
| Laporan diajukan | Pelapor + semua Pimpinan aktif | Laporan menunggu keputusan |
| Disetujui | Pelapor | Izin distribusi terbit |
| Ditolak | Pelapor | Laporan ditolak |
| Distribusi selesai | Pelapor | Distribusi selesai |
| Dibatalkan | Pelapor | Laporan dibatalkan |
| Koreksi izin | Pelapor + pimpinan lain | Izin distribusi dikoreksi |

- Notifikasi ditulis di dalam transaksi yang sama dengan perubahan status.
- Lonceng menampilkan 8 kabar terbaru; halaman `/notifikasi` menampilkan sampai 100 kabar dengan
  saringan “Hanya yang belum dibaca”, `Skeleton`, dan `EmptyState`.
- Membuka notifikasi akan menandainya dibaca lalu membuka laporan/izin yang terkait.
- Tidak ada WA/SMS asli; adapter masih mode simulasi.

## 4. Cetak Izin A4

| Pemeriksaan | Hasil |
| :--- | :--- |
| `@page size` | A4, margin 12 mm |
| Header aplikasi, navigasi, toast | Tersembunyi saat cetak |
| Header dokumen izin | Tetap tampil (bug `header` global M3 sudah diperbaiki) |
| Kolom catatan perhitungan | Tetap di layar, disembunyikan di kertas agar dokumen ringkas |
| Izin biasa | **1 halaman PDF** (`izin-distribusi-a4.pdf`) |
| Izin koreksi | **1 halaman PDF** (`izin-koreksi-a4.pdf`), mencantumkan izin yang digantikan + alasan koreksi |
| Nomor izin, posko, daftar bantuan, tanda tangan | Tampil lengkap |

`Page.printToPDF` dengan `preferCSSPageSize: true` menghasilkan satu halaman untuk kedua dokumen.

## 7. Catatan Teknis

- Migrasi `20261109085102_m5_notifikasi` menambah tabel `notifications` dengan relasi ke
  `users`, `incidents`, dan `permits`, indeks penerima/waktu, serta `onDelete: Cascade` untuk
  laporan dan `SetNull` untuk izin.
- Notifikasi **bukan** tabel append-only karena status baca berubah. Isinya tidak disunting;
  hanya `readAt` yang diisi.
- `seedDatabase` menghapus notifikasi lebih dahulu sebelum laporan/izin, sehingga reset tetap
  bersih dan cepat.
- Izin koreksi sekarang hanya menaruh alasan koreksi pada baris bantuan yang berubah; baris lain
  memakai alasan aslinya. Ini membuat dokumen cetak lebih ringkas dan jujur.
- Localtunnel adalah dependensi pengembangan; build produksi tidak memuatnya. Bila layanan
  diblokir, panduan menyediakan alternatif cloudflared/ngrok.

**Kesimpulan:** M5 memenuhi kriteria selesai — semua halaman lulus uji 4 lebar, README bisa
diikuti dari nol, tidak ada istilah teknis di layar, notifikasi berjalan untuk semua perubahan
status, dan izin A4 tercetak rapi satu halaman.
